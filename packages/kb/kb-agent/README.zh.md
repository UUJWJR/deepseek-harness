# @deepseek-ai/dsh-kb-agent

[English](README.md) | 中文

面向模型的 `kb-ask` 工具。每次调用解析一个已注册知识库，确保其已索引，检索带排名提示，然后派生一个只读子 agent 用 `read`/`grep`/`glob` 探索知识库根目录，并以引用来源作答。

## 工具

`kb-ask` 接收一个知识库名称和一个问题。子 agent 被一个只保留 `read`、`grep`、`glob` 的工具过滤器约束；write、edit、bash 与派生工具会从其提示词中消失并拒绝执行。子 agent 的提示词携带知识库根的绝对路径、一个浅层目录映射，以及被框定为不精确起步线索的检索提示。

## 模型体验

### kb-ask 工具

#### 模型看到的内容

一个带必填 `kb` 名称与必填 `question` 的工具。工具描述与参数 schema 固定；返回的答案是只读子 agent 的最终文本。

#### Token 影响

固定、常驻的 schema 与描述成本；每次调用的答案文本是唯一随数据变化的内容。

#### KV Cache 影响

工具 schema 前缀稳定；答案是一次独立的子请求，不共享父级缓存前缀。

### 只读子 agent 提示词

#### 模型看到的内容

一个命名知识库根、带深度限制的目录映射与检索提示的提示词，指示子 agent 仅在该目录内用 read/grep/glob 探索并引用源文件。

#### Token 影响

每次调用；随目录映射大小与配置的提示数量增长。

#### KV Cache 影响

每次调用独立请求；其前缀取决于提示词布局，而非先前轮次。

## 已知限制与暂缓事项

- **以提示词携带根路径，而非进程 cwd** — subagent seam 从父级派生子 agent 的 cwd 且不提供逐子覆盖，因此知识库根以提示词传递，而非设为子 agent 工作目录。
- **只读靠工具过滤器，非文件系统策略** — 子 agent 无法写入或执行，但该保证是工具面限制，而非操作系统级沙箱。
